Production Paradigm: System 1 Decision Router vs. Generative LLMs

In high-volume insurance payer workflows (EDI 837 claim ingestion), routing claims to adjudication queues, verifying clinical documentation completeness, and establishing statutory turnaround tiers has historically relied on either brittle heuristic regex rules or costly generative LLMs.

1. Single-Token Forward Pass Architecture

System 1 models evaluate state against a declared schema in a single forward pass without autoregressive text generation. The prompt presents lettered choices (A., B., C...) and extracts top-20 logprobs from the single generated answer token. Gemma 4 has multiple surface tokens for letters; mass is summed across duplicate tokens and scaled by calibration temperature:

P(choice_i) = p_i^(1 / T) / Σ_j p_j^(1 / T)   [Cygnet Recipe T = 3.4]

2. Apples-to-Apples Model Parity

Both local System 1 and System 2 backends execute on the exact same model weights (gemma-4-12B-it-Q8_0.gguf) running on the RTX 4090. Thus, any observed latency difference (e.g. 50ms vs 2,500ms) and token savings are strictly attributable to the inference paradigm, rather than differences in parameter count.

3. Multi-Question Adjudication Rubric

  • routing_queue (5-choice): auto_adjudicate, clinical_nurse_review, coding_audit_ncci, cob_subrogation, siu_fraud_review.
  • missing_clinical_docs (noul / binary): Calibrated probability of whether an operative report, pathology report, or imaging disc is missing from claim attachments.
  • urgency_tier (score / 3-level): standard_30_day, expedited_72_hr, stat_24_hr.

4. Confidence-Gated Cascade

Clear-cut claims (confidence ≥ 0.90) are auto-adjudicated instantly by System 1 in <100ms. Ambiguous edge cases (confidence < 0.90) trigger immediate escalation to System 2 to generate structured clinical rationale for a human nurse auditor.
